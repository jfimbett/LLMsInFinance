Mathematical Foundations of LLM Training

Model Optimization: Loss Functions & Probability

  • Core Objective: Learn probability distribution over tokens \[P(x_{t+1} | x_1, x_2, ..., x_t; \theta)\] where \(x_t\) = token at position \(t\), \(\theta\) = model parameters

  • Cross-entropy loss: Measures prediction error \[L_{CE} = -\sum_{i=1}^{|V|} y_i \log(\hat{y}_i)\] where \(y_i\) = ground truth distribution (typically one-hot encoded vector), \(\hat{y}_i\) = predicted probability, \(|V|\) = vocabulary size

  • From Logits to Probabilities (Softmax): \[P(x_i) = \frac{e^{z_i}}{\sum_{j=1}^{|V|} e^{z_j}}\] where \(z_i\) = raw model output (logit) for token \(i\)

  • Understanding Cross-Entropy Loss:

    Ground Truth Distribution:

    • In classification tasks: \(y_i = 1\) for correct class, \(y_i = 0\) for others
    • In language modeling: Next token prediction
    • One-hot encoding means only one token is “correct”

    Why It Works:

    • Penalizes incorrect predictions heavily
    • Rewards confidence in correct answers
    • Differentiable (allows gradient flow)

    Training Intuition:

    • Model learns to assign high probability to correct tokens
    • Low loss = good predictions
    • Model converges when loss is minimized

How Models Learn: Training Behind the Scenes

  • The Learning Process (Gradient Descent): Think of it like learning to ride a bike - you make mistakes, adjust, and get better

    • The model looks at its mistakes (called “loss”)
    • It figures out which direction to improve
    • It takes small steps in that direction
    • It repeats this millions of times

  • Smart Learning (Adam Optimizer): Like having a good coach who remembers your past progress

    • Remembers which improvements worked before
    • Adapts the learning speed for each part of the model
    • Prevents the model from “forgetting” what it learned

  • Training Tricks:

    Learning Rate Scheduling:

    • Start slow (warmup) - like warming up before exercise
    • Gradually slow down as training progresses

    Gradient Clipping:

    • Prevents the model from making huge, bad changes
    • Like having guardrails while learning

    Stability Techniques:

    • Mixed precision: Using different levels of math precision
    • Layer normalization: Keeping things balanced

Reasoning Models: Beyond Next Token Prediction

How Regular LLMs Work vs. Reasoning Models

  • How regular LLMs work:
    • Like completing a sentence one word at a time
    • Just predicts “what comes next” based on what it’s seen
    • No explicit thinking steps in between
    • Example: “The capital of France is ___” → “Paris”
  • What reasoning models do differently:
    • Think step-by-step before answering
    • Show their work like a student solving a math problem
    • Break complex problems into smaller pieces
    • Example: “What’s 13×27?” → “First I’ll multiply 3×7=21, then…”

  • In everyday terms:

    Regular LLM:

    • Like a quick gut reaction
    • “I just know the answer is X”

    Reasoning Model:

    • Like explaining your thought process
    • “I think X because of A, B, and C”

  • Why this matters:

    • Complex financial problems need step-by-step thinking
    • We want to see how the model reached its conclusion
    • Helps catch mistakes in the reasoning process
    • More transparent and trustworthy outputs

What Are Reasoning Chains?

  • A reasoning chain is:

    • A sequence of logical steps: \(R = \{r_1, r_2, ..., r_n\}\)
    • Where each \(r_i\) is one clear thinking step
    • These steps connect a question to an answer
    • Like showing your work in a math problem

  • Example: Multi-step reasoning

    Question: “What will happen if we mix baking soda and vinegar?”

    Reasoning chain:

    1. \(r_1\): “Baking soda is sodium bicarbonate (NaHCO₃)”
    2. \(r_2\): “Vinegar contains acetic acid (CH₃COOH)”
    3. \(r_3\): “When acids and bases mix, they neutralize each other”
    4. \(r_4\): “This reaction produces water, salt, and carbon dioxide gas”

    Answer: “The mixture will fizz and bubble as CO₂ gas is released”

  • Benefits of reasoning chains:

    Transparency:

    • Shows exactly how a conclusion was reached
    • Creates audit trail for verification
    • Helps explain decisions to others

    Error detection:

    • Easier to spot flawed assumptions

    • Can identify missing considerations

    • Enables targeted improvement of analyses

    • Reasoning chains document expert thinking

    • Makes complex analysis more teachable

    • Helps learners understand solution paths

The Math Behind Reasoning Chains

  • Regular LLM predicts next token: \[P(x_{t+1} | x_1, x_2, ..., x_t)\]

  • Reasoning Model builds step-by-step: \[P(A) = \prod_{i=1}^{n} P(r_i | Q, r_{1:i-1}) \times P(A | Q, r_{1:n})\]

    Where: \(r_i\) = reasoning step, \(Q\) = question, \(A\) = answer

  • Temperature controls exploration: \[P(x_i) = \frac{e^{z_i/T}}{\sum_{j} e^{z_j/T}}\]

    • High T: Creative, diverse paths
    • Low T: Focused, consistent
    • Zero T: Only most likely path

Why Temperature Cannot Be Zero in Reasoning

  • What happens when temperature is zero: \[\lim_{T \to 0} P(x_i) = \begin{cases} 1 & \text{if } i = \arg\max_j z_j \\ 0 & \text{otherwise} \end{cases}\]

    In plain English: The model always picks the single most likely option at each step, with no room for exploration

  • Why this is bad for complex reasoning:

    • It’s like always taking the first path you see
    • No ability to backtrack if you hit a dead end
    • Can’t consider alternative approaches
    • Gets trapped if the first step isn’t perfect

  • Real-world example: Investment analysis

    With zero temperature:

    • Model might only consider one economic factor
    • Gets stuck in a single analysis framework
    • Cannot adjust reasoning if assumptions are flawed

    With some temperature (T > 0):

    • Explores multiple economic scenarios
    • Considers different valuation methodologies
    • Can recover from initial incorrect assumptions
    • Produces more robust financial analysis

Information Theory Basics

  • Entropy in reasoning: \[H(R_i) = -\sum_{r_i} P(r_i | context) \log P(r_i | context)\]

    • Measures uncertainty in reasoning steps
    • Enables exploration of multiple solutions
  • Practical implications:
    • Balance between creativity and consistency
    • More entropy → diverse solutions
    • Less entropy → focused problem-solving

How Models Choose the Best Way to Think

  • Exploring multiple thinking paths: Like a chess player considering several moves ahead

    • Keep track of the most promising reasoning paths
    • Score each path based on how logical it sounds
    • Drop paths that don’t make sense

  • Quality control for reasoning:

    • Does this step make logical sense?
    • Is this factually accurate?
    • Are there any contradictions?

  • Why this approach is powerful:

    Reliability:

    • Multiple ways to solve the same problem
    • If one path goes wrong, others can catch it
    • Cross-checking between different approaches

    Confidence measurement:

    • When all paths agree → high confidence
    • When paths disagree → lower confidence
    • Shows uncertainty ranges in analysis

Reasoning Model Architectures

  • Chain-of-Thought (CoT): Finds the best reasoning path \[P(answer \mid question) = P(answer \mid question, thoughts) \times P(thoughts \mid question)\]
    • Linear reasoning progression, simple to implement and understand, good for sequential analytical tasks
  • Tree-of-Thoughts (ToT): At every step, explores multiple reasoning paths \[P(answer \mid question) = \max_{tree} \left( P(answer \mid question, tree) \times P(tree \mid question) \right)\]
    • Branching reasoning exploration, better for scenario analysis, higher computational cost
  • Graph-of-Thoughts (GoT): Identifies complex relationships between reasoning steps \[P(answer \mid question) = \sum_{graph} P(answer \mid question, graph) \times P(graph \mid question)\]
    • Complex relationship modeling, best for interconnected systems, highest computational complexity

How Are LLMs Trained?

How to Build an LLM

  • Step 1: Pretraining (Learning to Speak)
    • Think of it like teaching a child to read
    • The model learns language patterns from billions of texts
    • Develops basic understanding of grammar, facts, and reasoning
    • This is unsupervised learning - no human teachers needed!
  • Step 2: Fine-tuning (Learning to Help)
    • Supervised Fine-Tuning (SFT): Teaching it to follow instructions
    • Reinforcement Learning from Human Feedback (RLHF): Learning what humans prefer
    • Constitutional AI: Teaching it principles and values
    • Domain specialization: Extra training on finance-specific data
  • Two main approaches:
    • Open source models (like Llama, Mistral):
      • Trained on fewer instruction examples (5-25 million)
      • More transparent about how they work
      • Less safety filtering
    • Commercial models (like GPT-4, Claude):
      • Hundreds of specialized training datasets
      • Extensive safety and alignment work
      • Better at using tools and following guidelines

Training Data and Architecture

Common data sources:

  • Web Crawls: Common Crawl for General knowledge
  • Encyclopedic: Wikipedia for Facts
  • Books & Literature: BookCorpus for Narrative style
  • Code & Technical: GitHub for Programming
  • Specialized: Financial text for Domain expertise |

Fine-Tuning and Specialization

  • Instruction tuning (SFT):
    • Teaching to follow specific instructions
    • Using millions of instruction-response pairs
    • Creates basic assistant capabilities
  • Preference alignment:
    • RLHF: Learning from human feedback
    • Constitutional AI: Self-improvement via principles
    • Reduces harmful or incorrect outputs

Zero, One, and Multiple-Shot Prompts

Prompting Techniques Overview

  • Zero-Shot: Direct requests without examples
    • Simple, versatile, less control over format
    • Best for: Basic queries, explanations, general information
  • One-Shot: One example before query
    • Guides format and style consistency
    • Best for: Standardized reports, consistent formatting
  • Few-Shot: Multiple examples (3-5)
    • Establishes stronger patterns
    • Best for: Complex formats, specialized domains
